# Remaining Git Subprocess Commands to Migrate to GitPython

## Phase 2: Test Helper Migration (tests/helpers/git_helpers.py)
This file has 20+ functions that wrap git commands via subprocess. These should be migrated to use GitPython.

### git_helpers.py functions to migrate:
- [ ] git_run() - Base wrapper function (used by all others)
- [ ] create_commit() - Uses: git add, git commit -m, git rev-parse HEAD
- [ ] create_branch() - Uses: git checkout -b, git branch
- [ ] checkout_branch() - Uses: git checkout
- [ ] get_current_branch() - Uses: git branch --show-current
- [ ] get_current_commit() - Uses: git rev-parse HEAD
- [ ] get_commit_message() - Uses: git log -1 --format=%B
- [ ] get_branches() - Uses: git branch --format=%(refname:short)
- [ ] branch_exists() - Depends on get_branches()
- [ ] get_notes() - Uses: git notes --ref shortcake show
- [ ] add_notes() - Uses: git notes --ref shortcake add -m
- [ ] setup_remote() - Uses: git remote add
- [ ] push_branch() - Uses: git push [--force]
- [ ] fetch() - Uses: git fetch
- [ ] create_bare_repo() - Uses: git init --bare

## Phase 4: Test Assertion Migration
Many tests use subprocess to verify git state. These could use GitPython for cleaner assertions:

### Common patterns to migrate:
- [ ] git rev-list --count HEAD - Count commits
- [ ] git branch --show-current - Get current branch
- [ ] git log -1 --pretty=%s - Get commit subject
- [ ] git log -1 --pretty=%B - Get full commit message
- [ ] git show HEAD:<file> - Get file content from commit
- [ ] git log --format=%H - Get commit hashes
- [ ] git status - Check repo status

## Benefits of Migration:
- Consistent approach across codebase
- Easier to mock in tests
- Type-safe operations
- Better error messages
- Removes subprocess dependencies
- Cleaner, more maintainable code

## Migration Strategy:
1. Start with git_helpers.py (highest impact)
2. Update test fixtures to use the new helpers
3. Replace inline git subprocess calls with helper functions
4. Replace test assertions with GitPython-based checks
