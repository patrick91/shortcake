Stack your pull requests.

Shortcake turns a chain of branches into a reviewable stack — using nothing but a git trailer in each commit. No state files, no daemon — the whole stack lives in your history.

Why shortcake

Stacked PRs, without the ceremony.

No control file to keep in sync, no metadata branch, no background process. Your repository already knows how the stack fits together.

Trailers are the truth

Every branch records its parent in a Shortcake-Parent commit trailer. Nothing hidden, nothing extra.

Stacks track themselves

Branch on top of a branch and Shortcake keeps the whole chain ordered from main up.

Plays nice with plain git

Rebase, push, or branch with any git tool you like — the stack lives in your commits, so nothing breaks.

Adopt what you already have

Bring an existing branch into a stack with a single sc adopt.

The whole surface

A command set you can hold in your head.

Three verbs cover the loop: stack a new branch, adopt one you already pushed, and read the tree back. The state lives in your commits — so the commands stay small.

  • sc create -m …

    Branch off the current branch and record its parent in the first commit.

  • sc adopt <branch>

    Track an existing branch by writing its Shortcake-Parent trailer.

  • sc status

    Print the current stack as a tree, from main to your tip.

Shortcake-Parent: main

The trailer is the only metadata Shortcake stores. Rebase, push, or open a PR with any tool you like — the stack survives because it lives in the commit.
